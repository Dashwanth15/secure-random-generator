Why Randomness Matters in Cryptography

All modern cryptographic guarantees rely on secrets that an adversary cannot guess or compute.

🎲

Randomness

Values generated from unpredictable physical or operating system entropy.

↓
❓

Unpredictability

An attacker who knows previous outputs cannot compute or predict future values.

↓
🔒

Cryptographic Security

Keys, nonces, and session tokens remain confidential and tamper-proof.

The Core Cryptographic Distinction

Ordinary PRNGs (such as Python's random module using the Mersenne Twister) are designed for statistical uniform distribution and computational speed. They are deterministic mathematical algorithms. If an attacker discovers the internal state or seed, all past and future numbers are exposed.

CSPRNGs (such as Python's secrets module backed by os.urandom) harvest hardware entropy from the OS kernel (timing jitter, interrupt timings, device events). They are mathematically engineered to satisfy the next-bit unpredictability property.

⚠ Core Security Principle: If an attacker can predict a cryptographic key, nonce, or session identifier, encryption and authentication can be bypassed completely.

REAL-WORLD IMPLEMENTATION

Real-World Cryptographic Use Cases

Where is CSPRNG strictly required versus where ordinary PRNG is acceptable?

🔑

Cryptographic Keys

Symmetric keys (AES) and private asymmetric keys (RSA/ECC). A guessable key instantly breaks confidentiality and integrity.

CSPRNG Required
🔄

Nonces & IVs

Initialization vectors for AES-CBC and nonces for AES-GCM. Guarantees that encrypting identical messages produces different ciphertext.

CSPRNG Required
👤

Session Identifiers

Tracks authenticated web users. Guessable session IDs enable session hijacking attacks without requiring credentials.

CSPRNG Required
🛡️

Security Tokens

CSRF protection tokens, OAuth bearer tokens, and password reset links. Must resist brute-force and timing attacks.

CSPRNG Required
💡

When is Ordinary PRNG (random) Acceptable?

Ordinary PRNGs are faster and perfectly suited for non-security tasks: Monte Carlo simulations, statistical sampling, video game logic, procedural terrain generation, shuffling cards in casual games, and non-security unit testing.

SUMMARY FOR VIVA

Key Cryptographic Takeaways

Essential concepts to remember for demonstration and oral examinations.

  • 01
    Random-looking is NOT synonymous with cryptographically secure. A PRNG output may look uniformly distributed, but it remains deterministic and reproducible if the seed is known.
  • 02
    Ordinary PRNGs (Python's random) are vulnerable to state recovery. Observing 624 outputs of the Mersenne Twister allows an attacker to clone the exact internal state and predict every future value.
  • 03
    CSPRNGs satisfy the Next-Bit Unpredictability property. Backed by OS kernel entropy (hardware timings, interrupts), past outputs give zero computational advantage in predicting future bytes.
  • 04
    Security primitives depend strictly on CSPRNG. Cryptographic keys (AES), nonces (GCM), session IDs, and security tokens all fail critically if an attacker can guess or predict them.
  • 05
    Always use standard libraries: Python's secrets module. Never write custom random number algorithms or use random for passwords, tokens, keys, or nonces.
